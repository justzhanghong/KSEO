# 优化方法：从成本证据选择可验证动作

本页将 RSI 的优化思路整理为 **M13 总则与 17 个带条件方向**，接入 KSEO 原则 → 方法 → 场景规则 → 案例/来源的层级。来源为同事的 RSI 方法库，按相对路径、原文件 SHA256 与明确边界引用，不要求运行时访问外部目录，也不自动安装或执行这些 skills。

本次没有新 GPU 测量或新增成功案例。资源算例、静态走查和历史 RTX5090 小样本不变成新模型收益，也不构成近似算法或降低精度的授权。

## 使用

```bash
kseo knowledge --node M13
kseo knowledge --node RSI-15
kseo knowledge --hierarchy --context examples/knowledge/kernel-method-context.json
```

层级检索及 Agent 请求中的 `knowledge_hierarchy.optimization_methods` 总是携带方法导航和 M13 总则，既有 top-k 和现行规则不变。方向的完整内容在明确选择 `context.optimization_method` 后参与规则检索，或通过 `--node` 下钻。未知成本条件不假定存在，导航命中也不代表已匹配或验收通过。

## M13：最小可证伪实验

1. 冻结真实调用边界、数学/数值合同、shape/stride/尾部、源码/镜像/编译与设备身份；先检查baseline自重复。
2. 把成本证据、成立条件、唯一动作、控制版、可证伪预测和否决条件写清；不固定遍历全部方向。
3. 编译相关改动核对实际同源产物与全kernel REG/SMEM/local、同步和动态工作；进程/模型复用按生命周期证据验收。
4. 数值通过后同设备交错测未插桩完整调用，包含准备、查键、分配、同步和排空；Profiler只辅助归因。
5. 遵守单shape model-forward warmup与跨shape、并发、缓存合同；单项有效后重测组合，不能相加历史百分比。
6. micro收益必须回到TTFT/TPOT、质量、API、稳定性与最终新部署；未能隔离时只报告组合效果或证据不足。

瓶颈分析员引用当前 Profile，选方向并提出预测；开发人员保持唯一动作并提供等价说明；独立 Validator 核对冻结 oracle、原始结果和实际产物；System 以 E2E 证据决定保留或回退。自然语言说明、少指令或更高 occupancy 均不能单独证明收益。

## 带条件的动作与反证

<a id="rsi-01"></a>
### RSI-01 缩短中间值存活区间

方法标记：`shorten-live-ranges`。临时值跨多个阶段存活，REG/local 或依赖等待可能限制热点。

- **成立条件**：生成可合法延后或最终消费可提前，且不改变输入版本、算术和副作用。
- **最小动作**：只移动一个中间对象的生成或消费点，先保持存放位置、tile和计算次数不变。
- **控制实验**：原版与仅移动版；若增加重算，再用保持同样重算但原寿命的版本隔离成本。
- **预测**：目标工作集/存活区间下降，并在实际资源或关键路径上体现。
- **否决条件**：新增重算、延长其他值寿命、REG分配未变或完整调用没有净收益。
- **验收证据**：同源资源报告与SASS、目标对象读写/版本、完整输出与未插桩计时。

来源：`rsi:S04`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-02"></a>
### RSI-02 选择状态存放位置

方法标记：`state-placement`。某个累加器或中间状态占用限制性存储资源。

- **成立条件**：目标设备支持候选存储和访问方式；已明确所有读者、精度、布局与完成语义。
- **最小动作**：只迁移一个对象，在寄存器、共享内存或合法重算之间比较，保持原累加与舍入规则。
- **控制实验**：原版与迁移版；有必要时仅预留同等存储作容量控制，并披露真实分配变化。
- **预测**：原限制资源下降，额外搬运和同步能被实际重叠或摊销。
- **否决条件**：二次staging、布局转换、同步或另一资源限制抵消收益；读者未结束就回收。
- **验收证据**：完整搬运路径、REG/SMEM预算、同步/别名检查、数值与完整调用耗时。

来源：`rsi:S05`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-03"></a>
### RSI-03 分块与驻留联合调参

方法标记：`tiling-residency`。tile或线程映射与复用、MMA效率、实际驻留发生冲突。

- **成立条件**：已冻结完整问题和真实shape分布；区分独立输出分片与需要合并的部分归约。
- **最小动作**：先固定tile只改线程映射，再固定映射只改一维tile，记录覆盖完整问题所需的CTA数。
- **控制实验**：原版和各单变量版；归约变化时另保留同分片、原合并顺序的控制。
- **预测**：资源跨过实际限制阈值，或相同驻留下有更多可发射工作隐藏等待。
- **否决条件**：重复读取/合并增加、矩阵指令效率降低、网格不足、新spill或完整负载无收益。
- **验收证据**：真实launch及编译资源、分配取整、动态驻留/eligible工作、完整输出和调用计时。

来源：`rsi:S06`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-04"></a>
### RSI-04 GPU线程角色分工与工作分配

方法标记：`role-partitioning`。producer/consumer等GPU线程角色的计算、供数与等待分布不均。

- **成立条件**：明确每个角色的输入输出、集体参与范围、依赖和恰好一次处理要求。
- **最小动作**：先固定总线程数，仅改变一对角色的工作分配；增减线程作为后续独立候选。
- **控制实验**：原版、分工版及保持同映射与必要握手的控制；不同时删除barrier。
- **预测**：关键消费者更早完成，完整kernel成本降低，而非单个角色更快。
- **否决条件**：新增同步、串行化、REG/SMEM跨阈值、漏工作、重复工作或死锁。
- **验收证据**：各角色工作/等待、真实资源、参与人数、空/尾/不等长路径与完整结果。
- **专项边界**：角色指GPU线程/warp分工；不能据此给TP/PP分配或Agent角色作性能结论。

来源：`rsi:S07`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-05"></a>
### RSI-05 按完整依赖调整GPU发射顺序

方法标记：`readiness-aware-scheduling`。已就绪消费者被另一项固定优先工作阻塞。

- **成立条件**：全部输入、旧输出与目标缓冲均安全；确认query是否只读以及acquire的实际副作用。
- **最小动作**：保持角色、槽数和发布粒度，仅交换一处合法工作顺序，保留issued/completed/released状态。
- **控制实验**：原版、相同查询但保持原序、允许改序三版，隔离查询开销与改序收益。
- **预测**：关键消费者真正提前完成，完整依赖链缩短。
- **否决条件**：等待只转移、预取被推迟、查询成本抵消、重复发射/释放或phase错代。
- **验收证据**：真实同步API语义、完整依赖、冷热/尾/排空/回绕检查与未插桩计时。

来源：`rsi:S08`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-06"></a>
### RSI-06 分段发布与分段消费

方法标记：`segmented-publication`。整块发布拖延了消费者，而消费者存在合法的分段输入边界。

- **成立条件**：最小消费粒度与布局已知；必要全局统计已经完成，每段所有权和可见性可证明。
- **最小动作**：仅将一次整块发布改为一种合法段长，先保持角色、槽数、线程映射和元素算术不变。
- **控制实验**：整块原版、分段通知但整块消费、真正分段消费三版。
- **预测**：首个可消费片段和整个算子的完成时间都提前。
- **否决条件**：消费者仍需整块、额外通知/重复读取抵消；全局统计未完成或仍有读者就复用。
- **验收证据**：逐段有效范围、恰好一次消费、事务计数/fence、尾段及完整调用计时。

来源：`rsi:S09`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-07"></a>
### RSI-07 预取窗口与环形缓冲优化

方法标记：`prefetch-ring-buffers`。输入等待、预取距离、槽数或过晚释放处于关键路径。

- **成立条件**：每代槽的所有读者、index/phase、真实异步完成和安全复用点明确。
- **最小动作**：先固定深度只改距离，再固定距离只改深度，最后单独评估安全release点。
- **控制实验**：原版与每个单变量版；增加查询时保留查询不改变调度的控制。
- **预测**：实际输入更早就绪，首轮、稳态和排空合计成本下降。
- **否决条件**：缓冲变多降低驻留、等待迁移、缓存竞争、槽耗尽或issue后过早释放。
- **验收证据**：槽容量/资源、发射/完成/释放事件、短于槽数/多次回绕/非对称消费者及完整计时。

来源：`rsi:S10`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-08"></a>
### RSI-08 索引表示与解码优化

方法标记：`index-encoding`。稀疏索引的delta累计形成串行链，或索引存储可能过宽。

- **成立条件**：已知绝对值、delta、sentinel、重复项、负值和累计/乘法中间值范围。
- **最小动作**：先在相同位宽比较absolute与delta，再单独比较有范围证明的窄存储，保持有效序列与顺序。
- **控制实验**：原版、仅表示变化、仅合法窄存储；准备与上传成本分别计入。
- **预测**：累计依赖或元数据字节减少，完整调用仍有净收益。
- **否决条件**：截断/溢出、保留码冲突、重复或顺序改变，或格式转换/准备成本抵消。
- **验收证据**：逐项解码序列、范围端点/空尾/sentinel检查、动态访存与完整调用计时。

来源：`rsi:S11`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-09"></a>
### RSI-09 关联元数据缓存与复用

方法标记：`metadata-cache`。多个GPU角色重复读取相同一代的ID、scale或descriptor。

- **成立条件**：完整版本快照一致，明确所有消费者、缓存发布与旧读者完成后的失效/回收。
- **最小动作**：先缓存一个小窗口的关联项，保持payload布局、索引编码和遍历顺序不变。
- **控制实验**：无缓存、同窗口单项、配对和整表缓存；窗口长度单独调参。
- **预测**：重复读取/地址等待减少，同时准备、同步和资源成本可接受。
- **否决条件**：仅ID相同却scale已变、快照不一致、提前覆写，或共享内存增长降低驻留。
- **验收证据**：ID/scale对应、仅scale变化/并发读者/回绕、真实请求/字节与完整净成本。

来源：`rsi:S12`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-10"></a>
### RSI-10 地址计算外提与简化

方法标记：`address-hoisting`。热循环反复计算batch/head等不变量地址部分。

- **成立条件**：编译器尚未完成同样外提；已证明地址范围、符号扩展、stride和中间乘法合法。
- **最小动作**：仅外提一个不变基址；位宽缩小另列候选，保留宽指针高位和合法符号扩展。
- **控制实验**：原版、仅外提、仅合法位宽改写；单项有效后再比较组合。
- **预测**：热循环地址指令或串行依赖减少，完整资源和耗时不恶化。
- **否决条件**：指针截断、地址错位、外提值延长寿命跨过资源阈值或编译器原已优化。
- **验收证据**：逐项地址、batch/head/stride/边界范围、同源SASS及完整数值/计时。

来源：`rsi:S13`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-11"></a>
### RSI-11 精确跳过恒等数据操作

方法标记：`exact-noop-elimination`。热点中存在可廉价且充分证明的恒等更新。

- **成立条件**：证明实际数据路径、输入域、signed zero/非有限值和副作用；集体参与条件一致。
- **最小动作**：仅在充分条件成立时跳过数据更新，保留必要acquire/release/fence/通知和正确事务计数。
- **控制实验**：原版、相同判断但仍执行、精确跳过三版。
- **预测**：合法命中分布下省去工作的成本超过判断/汇合，且确实改善关键路径。
- **否决条件**：把近似等于恒等值当精确条件、忽略特殊值、漏通知或成本被并行工作完全隐藏。
- **验收证据**：等价性与输入域、边界/混合参与/交替路径、实际跳过产物和完整净成本。

来源：`rsi:S14`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-12"></a>
### RSI-12 不变计算预计算与版本化缓存

方法标记：`invariant-precomputation`。相同依赖版本下重复进行确定性准备或子表达式计算。

- **成立条件**：完整依赖含内容、权重、scale、shape/stride、配置与实现；RNG和副作用不因缓存改变。
- **最小动作**：只缓存一个确实不变的子表达式，按一致快照生成，真实写入完成后发布并保留旧读者代次。
- **控制实验**：原版、相同查键但重算、缓存三版；分别测首次、命中、失效及实际复用期。
- **预测**：包含准备、查键、驻留和失效后，实际有效复用期内的总成本更低。
- **否决条件**：缓存当前输入相关输出、shape相同但内容已变、RNG消费改变、过期或发布竞争。
- **验收证据**：完整依赖键/代次、并发与stream事件、失效/回退、容量和完整调用计时。

来源：`rsi:S15`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-13"></a>
### RSI-13 成组转换与直接打包

方法标记：`paired-conversion-packing`。转换重复输入同一值，随后需要多余掩码或字节置换。

- **成立条件**：目标架构支持相应转换；逐元素scale、舍入点、饱和/非有限值语义及消费位序已知。
- **最小动作**：用两个不同元素匹配合法成组转换并形成正确位序，先保持原store和线程映射。
- **控制实验**：原版、仅成组转换、成组后显式恢复原排列的控制。
- **预测**：转换/掩码/置换动态工作减少，没有REG/local或其他发射路径回退。
- **否决条件**：scale跟错元素、位序错误、提前舍入、换量化格式或硬件不支持原生路径。
- **验收证据**：互异值与scale、舍入中点/特殊值/尾部、实际指令及完整输出/计时。

来源：`rsi:S16`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-14"></a>
### RSI-14 向量访存与输出映射

方法标记：`vector-memory-access`。连续数据使用细粒度load/store，地址与请求成本可见。

- **成立条件**：逐项证明连续性、首址和stride对齐、整个向量有效、所有权及语言别名规则。
- **最小动作**：先只改load或store之一，合法主体使用宽访问，尾部保留安全短向量/标量路径。
- **控制实验**：原版与合法宽访问版；需要映射重排时另列候选并计入shuffle/同步。
- **预测**：目标宽指令和动态请求/地址成本下降，完整算子有净收益。
- **否决条件**：先越界读取再mask、覆盖padding或相邻行、同步/可见性语义改变，或布局成本抵消。
- **验收证据**：stride/偏移各余数、短尾/哨兵、真实请求/sectors/DRAM字节与完整计时。

来源：`rsi:S17`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-15"></a>
### RSI-15 静态索引消除私有数组访存

方法标记：`static-indexing`。小型线程私有数组经runtime固定遍历产生LDL/STL。

- **成立条件**：源码/地址偏移已定位目标对象；遍历原本固定，真正数据依赖索引保持原语义。
- **最小动作**：仅对一个小对象改用编译期索引展开，保持访问顺序、表达式、舍入与输出宽度。
- **控制实验**：原runtime遍历、单对象静态展开；必要时比较部分展开。
- **预测**：目标local访问消失或减少，而全kernel资源和完整耗时改善。
- **否决条件**：零spill被误当零local、REG增长降低驻留、代码膨胀或强行把动态索引写死。
- **验收证据**：同源REG/STACK/local/spill和SASS、真实动态路径、尾部与完整输出/计时。

来源：`rsi:S18`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-16"></a>
### RSI-16 源表达与全Kernel机器码回归分析

方法标记：`codegen-regressions`。局部表达更短但其他路径变化，或两个单项优化组合退化。

- **成立条件**：锁定实际源码、编译器/flags、launch、输入和真实PTX/CUBIN/SASS身份，保持数学合同。
- **最小动作**：一次只换一种同语义表达或编译原语，检查整个kernel的控制流、同步、资源和冷热角色。
- **控制实验**：原表达与每个单项；发生组合疑问时做A、X、Y、X+Y同场四版。
- **预测**：目标动态工作减少且没有非局部关键路径/资源回退。
- **否决条件**：以静态条数断言提速、仅查目标算术附近、组合未经重编译复验或偷换近似算法。
- **验收证据**：同源产物/资源、相关动态指标、完整数值、未插桩样本及组合复验。

来源：`rsi:S19`, `rsi:S21`；方法描述已审阅，当前模型未实测。

<a id="rsi-17"></a>
### RSI-17 跨请求模型复用与按需驻留

方法标记：`model-lifecycle-cache`。重复正式请求实际包含worker启动、模型构建或权重重读。

- **成立条件**：存在目标重复成本；完整工作集容量可承受；不可变状态、请求/会话状态及版本代次可隔离。
- **最小动作**：只延长一个资源生命周期，按证据选仅复用worker、GPU常驻或CPU模型池，不预设搬运方案。
- **控制实验**：同设备同环境原版与所选分支，交错测量；多项一起改变只报告组合效果。
- **预测**：含启动/准备/迁移/清理及实际复用期后，总成本下降。
- **否决条件**：vLLM已常驻且无目标重建成本、会话串用、版本失效、容量不足或迁移成本抵消。
- **验收证据**：加载/构建/迁移实际行为、量化/布局/别名、请求隔离/取消、RAM/GPU峰值及完整请求计时。
- **专项边界**：通常常驻的vLLM服务不应无证据增加CPU模型池；这不等于KVOffloading。；来源的RTX5090三类任务复用同一Qwen CPU模型池，是组合历史结果及小样本；不能推出跨模型收益，原始summary未在KSEO重跑。

来源：`rsi:S20`, `rsi:S21`, `rsi:S22`, `rsi:S23`；方法描述已审阅，当前模型未实测。

## 共同边界

- 数学与数值：当前任务及 G-P01 优先；保留必要副作用和输入版本。浮点微差按冻结容差，不凭质量分数认可算法变化，也不把源案例的逐位合同全局化。
- 硬件：SM80 先核对实际指令和同步能力；TMEM、tcgen05 等 Blackwell 专用实现不能直接使用，原文资源算例不是 A800 实测参数。原生 FP8 转换也须核对支持。
- 负载：真实 shape、阶段与分布先冻结；只 warmup 一个声明的 model-forward shape。isolated kernel 预热不能成为正式测速逐 shape 预跑模型的理由。
- 测量：同设备、同身份交错对照，计入准备、检查、迁移、释放与排空；首次、命中、失效和有效复用期分别报告。Profiler 只作归因，不直接当正式速度。
- 组合：单项有效后重编译并重做数值与计时；需要时 A/X/Y/X+Y 对照，不相加历史收益；无法隔离就报告联合净效果。
- 范围：GPU线程/CTA流水线与host调度分开确定验证边界；这些方法没有提供通用TP/PP胜负或跨节点P/D收益结论。
- 最终验收：局部通过后仍需按当前合同完成 TTFT/TPOT、质量、API、稳定性及 fresh deploy；GSM8K 和 RTLBench/LongBench/LiveCodeBench 的职责及本地集合不变。
